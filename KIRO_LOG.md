## Hooks
- [Step 3] hooks — Built 3 agent hooks in `.kiro/hooks/` (+ backing scripts in `tests/`):
  - **test-on-save** (`PostFileSave`, matcher `^(lib|tests)/.*\.ts$`) → runs `npm test` (Vitest, `vitest run`, no watch) and reports failures.
  - **copy-guard** (`PostFileSave`, matches `lib/i18n/**`, `components/**`, `app/**/*.tsx`) → runs `tests/copy-guard.mjs`: flags forbidden phrases in EN/ES/PT/HT/ZH and English copy above 8th-grade reading level. Dependency-free; grades only real sentences (≥8 words, ends in punctuation) to avoid false positives on short UI labels; exempts the fixed disclaimer.
  - **update-docs** (manual, `UserPromptSubmit` matcher "update docs") → `tests/update-docs.mjs`: appends a dated entry to KIRO_LOG.md and refreshes the README "How we used Kiro" section.
- [Step 3] hook:copy-guard TEST — Wrote a scratch file with the forbidden phrase "you qualify for this trial"; copy-guard flagged it and exited 2:
  `[forbidden:en] "you qualify" in tests/scratch-copy.ts -> Good news — you qualify for this trial.`
  Also verified Spanish detection (`[forbidden:es] "usted califica"`). Reverted the scratch file. **(screenshot this firing for the demo video.)**
- [Step 3] hook:copy-guard FINDING — Running copy-guard on the real `lib/i18n/en.ts` flagged one legit over-limit string (grade 8.4 > 8): `results.tryWider` "Try a larger distance, or a more general word (for example \"diabetes\" instead of \"type 2 diabetes\")." Flagged to Neil (owner of i18n) to simplify — not editing his file directly per ownership rules.
- [Step 3 fix] hook:copy-guard SILENT-PASS fixed — Hasan found the hook exited 0 ("no files given") when invoked with no file args, so it would pass without checking. Fixed `tests/copy-guard.mjs`: with no args and no usable stdin JSON it now **default-scans** all of `lib/i18n/`, `components/`, and `app/**/*.tsx` and exits 2 on violations (never a silent pass). Also made stdin non-blocking on a TTY (was hanging), and added a CSS/Tailwind-class heuristic so `className` strings aren't graded as prose (killed a false positive on `components/LineChip.tsx`). Default scan now reports only the one real finding (Neil's `results.tryWider`).
- [Step 3 fix] hooks FORMAT corrected (via Kiro introspect/docs) — Authoritative hook docs showed three format bugs: trigger `PostFileSave` → **`FileSave`**; `UserPromptSubmit` → not a manual trigger (fires on every prompt); `timeout` must sit at the **hook level**, not inside `action`. Fixed all three JSON files. For the manual update-docs: v1 has no runnable manual trigger, so added a **manual-inclusion steering command** `.kiro/steering/update-docs.md` (runs as `/update-docs`) as the invokable counterpart; kept the hook file (trigger `Manual`) to document intent + list it in the panel.

So firing was verified by invoking the backing scripts exactly as a `FileSave` hook would (JSON file path on stdin): scratch copy "you qualify for this trial" → `[forbidden:en] "you qualify"`, exit 2; reverted. **To verify the hooks actually fire on save, run them in the Kiro IDE or CLI** (check the Agent Hooks panel / `/hooks`) — do this on a local machine before relying on them. **(Screenshot the panel + a save-triggered fire for the demo video.)**

## MCP
- [Step 4] mcp:fetch CONFIG — Added the fetch MCP server to `.kiro/settings/mcp.json` (`command: uvx`, `args: ["mcp-server-fetch"]`, `autoApprove: ["fetch"]`). Kiro Web *does* run MCP servers (unlike hooks), but they load at sandbox start, so this one will be available in the next session / in the IDE.
- [Step 4] mcp:fetch RAN IN WEB? — **No live fetch was possible in this session.** The sandbox network mode is **INTEGRATIONS_ONLY** (no external internet): both `curl` and web_fetch to `clinicaltrials.gov` and `api-v3.mbta.com` returned **403 CONNECT tunnel failed**. So the fetch MCP server cannot reach those hosts from this sandbox regardless. **To do the live probe, run it in a Kiro IDE/CLI session (or a Web sandbox set to OPEN_INTERNET).** The config is in place so it "just works" there.
- [Step 4] API field reference (from v2/v3 API **docs**, not a live probe — verify once the fetch MCP runs with internet):
  - **ClinicalTrials.gov v2 `eligibilityModule`** — fields: `eligibilityCriteria` (one free-text blob with "Inclusion Criteria:" / "Exclusion Criteria:" headers), `healthyVolunteers` (bool), `sex` ("ALL"|"FEMALE"|"MALE"), `minimumAge` / `maximumAge` (strings like "18 Years", "6 Months", or **absent**), `stdAges` (["CHILD","ADULT","OLDER_ADULT"]). Age is a **string with units**, not a number → `parseAge` must handle "Years"/"Months"/"Weeks"/"Days" and missing bounds.
  - **`contactsLocationsModule.locations[]`** — `facility`, `city`, `state`, `country`, `status`, and optional **`geoPoint {lat, lon}`**. `geoPoint` is frequently **missing** (older records, non-geocoded sites) → distance code must skip/flag sites with no geoPoint.
  - **`centralContacts[]`** (under `contactsLocationsModule`) — optional array; items have `name`, `role`, `phone` (may include `phoneExt`), `email`. Any field can be absent; the whole array can be absent → contact UI needs a "no contact listed" fallback.
  - **MBTA v3 `/stops` `wheelchair_boarding`** — integer **0 = no info, 1 = accessible, 2 = not accessible** (note: 0 ≠ inaccessible; it's "unknown"). Maps to the three i18n strings `go.accessible` / `go.notAccessible` / `go.accessUnknown`.
  - **Edge cases to code for:** missing `minimumAge`/`maximumAge` (open-ended range); age in **Months/Weeks/Days** not Years; `"N/A"` / empty `eligibilityCriteria`; location with **no `geoPoint`**; trial with **no MA site** after filtering; `centralContacts` absent or missing phone/email; `wheelchair_boarding == 0` (unknown, not "no"); MBTA returning **zero stops** in radius.
